# titan-chordpro-ui agent

1. Read [`docs/VISAO.md`](docs/VISAO.md) (product SoT) and [`SPEC.md`](SPEC.md) (engineering contract) end-to-end.
2. Stack **ratified:** Vue-first UI + TypeScript **core** (no Vue in core) + agnostic controller; React/CE bindings later under demand — see `docs/analysis-expansao-futura.md`.
3. Implement in the order of SPEC §10.
4. Claim DONE only when SPEC §9 acceptance table is green (core + Vue package rows).
5. Do not invent ChordPro fixtures — use `fixtures/`.
6. **No Vue imports in core** (`src/core/**` or equivalent). Vue UI lives in `src/vue/**` or package entry `@henryavila/titan-chordpro-ui/vue`.
7. Do not add a runtime `VisualAdapter` / multi-stack plugin registry in v0.1.
8. Naming lock: [`docs/NAMING.md`](docs/NAMING.md). The 2026-08 repository handoff is historical; its instruction to keep `ChordproViewer` and `cpv-*` has been superseded.
9. **`x///` is the clock, not lyrics.** `x` is always the **head** of the time; `/` is a beat that is not. `[Cm]//` with no `x` is two beats in 4/4 (also as a phrase tail). Voiceless stretches: `[G]x///`. SoT: [`docs/MARCAS-X.md`](docs/MARCAS-X.md). Do **not** strip those marks from the source to “clean” a lyric. Só letra hides them in the **reading projection** only (`stripChordClock` + `stripBeatMarks` — marks glued after a removed chord must not leak; keep `cami/nhar` and letter-x in words). Host prop: `lens="letra"`. Do not guess bars from chord count. Do not treat a sung-line tail as the duration of the whole verse. Do not require `x` on every group.
10. **Auto-scroll tests never use the unmarked-row estimate as expected time.** Seconds come from the fixture: `{duration:}`, `{tempo:}`, `{time:}`, `x///` counted in the source, lyric text in the file, real DOM. Never `BEATS_PER_ROW`, never “8 pulsos por linha”, never `rows * 8 * 60/bpm`. Gate: `tests/core/autoscroll-no-estimates.test.ts`. `tests/core/timeline.test.ts` may mention `BEATS_PER_ROW` only as the engine unit under test, not as a song’s verse duration.
11. **Semver:** feature = MINOR, bugfix = PATCH. Never ship `feat` / changelog Added|Changed as a patch (`0.1.3` + features → `0.2.0`, not `0.1.4`). Baseline is npm latest, not the last GitHub tag. Run `pnpm release` — do not pick the bump by hand. Skill: `.grok/skills/release/SKILL.md`.
12. **Changelog and the GitHub Release are the same text**, Portuguese, for a person using the app: where it is, what they do, what they see. Do not write a line that needs the source to understand (`chrome`, `recolhido`, `stdShapeKey` as the sentence). Write it under `## [Unreleased]` when the change lands, not only at ship time. How: `.grok/skills/release/SKILL.md` (Notes a person can read).
13. **Custom directives use `x_titan_`**, including `x_titan_score` and the inline pair `x_titan_start_of_score` / `x_titan_end_of_score`. No aliases or automatic conversion from the former names. Standard ChordPro directives and `x///` clock marks are unchanged. Contract and consumer migration: `docs/NAMING.md` and `docs/CONSUMER.md`. The release must communicate this breaking change and the required consumer adjustments explicitly.

14. **Padrão visual da TAB:** siga [`docs/NOTACAO-VISUAL.md`](docs/NOTACAO-VISUAL.md). Mínima = uma haste com 50% da semínima na base; no estendido, a mínima não cresce. Não substituir por haste dupla do LilyPond nem usar o default do motor como especificação.
15. **Solution identity:** Vue export `<TitanChordpro>`, parsed model `TitanChordproDocument` / `TitanChordproSection` / `TitanChordproLine`, controller `createTitanChordproController`, CSS/DOM namespace `titan-chordpro-*`, stored-key namespace `titan-chordpro:`. Keep the repo, npm package and CLI named `titan-chordpro-ui`. Do not export old component/type/controller aliases or emit old CSS/DOM names. Keep `view`/`edit`, `x_titan_*` and `x///` unchanged. Validate with `pnpm build`, `pnpm typecheck`, `pnpm test` and browser tests before claiming the rename complete.
